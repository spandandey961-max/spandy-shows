# Spandy Shows trace v1

The authoritative definitions are `backend/schema.py`; its Pydantic models also produce a machine-readable JSON schema in `docs/trace.schema.json`. The browser types correspond to this format.

Each trace includes schema version, language/runtime version, submitted source filename and SHA-256, status/termination reason, diagnostics, limitations and ordered independent snapshots. Worker results are untrusted until validated.

`POST /api/jobs` accepts `execution: "visualize"` (the default) or `"run"`. Run code returns one final completion/termination observation and has no snapshot-step limit. Python may include bounded final globals/objects. Native run mode returns output and diagnostics without fabricated frame or object observations. Saved-program/share requests use the unchanged `Program` payload without this job-only field.

`line` and `call` snapshots are **before** the highlighted source instruction executes. Python/JDI `return` snapshots show the suspended returning frame and returned value **after** the return was determined. C detects returned calls when stack depth shrinks: its `return` snapshot is the caller **before** the highlighted line and carries an explicit note. Completion/termination has no source highlight. Source lines may correspond to several statements in Java or C; debugger line information does not give subexpression execution steps.

Frames are ordered from outermost to innermost. Frame IDs remain stable for a live call and change for a new call, including recursion. Values distinguish primitive/reference/null/uninitialized/unavailable/optimized-out. This implementation uses `unavailable` or notes when initialization cannot be known; it does not pretend to detect C uninitialized memory. Large integers beyond JavaScript's exact numeric range are represented as decimal strings with their original numeric type.

Object IDs are stable for Python and JDI heap identity, and stable by observed address and type for C storage. C address identity does not prove allocation lifetime or validity. Each snapshot has fresh object records; later mutations never alter prior snapshots. Nested, shared and circular references point to a single snapshot object map. Strings, collection lengths and traversal bounds have explicit truncation flags. Unsupported inspection is labeled unavailable.

Recorded stdout/stderr is cumulative up to the snapshot. Python capture is separate from the JSON result file. Java drains separate debuggee streams while the JVM is suspended. C uses unbuffered redirected files. Compilation failures produce diagnostics and no fabricated steps. External limits/cancellation retain the last validated checkpoint and bounded captured output when available; no new variable state is invented after a process is killed.

`completed`, `failed`, `truncated`, and `cancelled` are trace statuses. Termination reasons include completed, syntax_error, compilation_error, runtime_error, unsupported_feature, worker_unavailable, worker_error, timeout, memory_limit, disk_limit, step_limit, output_limit, trace_limit and cancelled. Requests and queue/rate/origin errors are structured API errors.

Python uses the existing call/return events for resumable frames. A return with note `yield` records a generator yielding a value; note `suspend` records async suspension. A subsequent call with note `resume` keeps the same frame ID. These pauses are not final function returns. Standard-library implementation lines are excluded; callbacks in main.py remain traced.

## Live input protocol

Job-only `interactive: true` enables pause/resume input. Legacy jobs default to `false` and consume pre-supplied stdin. GET `/api/jobs/{id}` returns `queued`, `running`, `waiting`, or a final trace status, plus `live: {stdout, stderr, input}` while a worker is active. Pending input is `{id, line, type}` with type `integer`, `number`, `character` or `text`. Labels guide the form; language runtime conversions remain authoritative.

POST `/api/jobs/{id}/input` accepts `{id, text}` for the current read. IDs are sequential and stale/duplicate submissions return 409; cumulative input exceeding 4 KB returns 413. GET `/api/jobs/{id}/trace` can return the immutable recorded prefix while waiting; job status is authoritative about whether execution has ended (a checkpoint's trace status is provisional). The prefix ends before the input instruction. Final traces retain the same earlier snapshots. Run mode streams output and input requests but records only its final observation. New termination reason `input_timeout` means the input idle limit expired.

## Preparation and playback

Job status includes `live.traceSteps`, the count in the latest immutable checkpoint. Visualize publishes the first real debugger snapshot immediately, then checkpoints at most about five times per second or every 64 newly recorded states; actual input reads force the exact prefix to disk before exposing their request. Recording and the browser cursor are independent. Completion, new input and errors never automatically select the last step. C collects frame IDs, input visibility and bounded typed observations in one GDB Python query per user stop, preserving nested storage identities and pointer offsets. User line breakpoints avoid stepping through library instructions for small line tables; large line tables retain normal stepping to avoid quadratic breakpoint overhead. Java batches visible locals/static values and captures stdout synchronously at suspended snapshots. Windows atomic checkpoint replacement retries short reader sharing conflicts. Limits are shared by workers, schema and health metadata: 20,000 steps, 64 MiB trace and a 300-second Visualize preparation budget; Run code retains its separate 60-second budget.

A reference Value can include an optional `path` (an empty list by default). Numeric members select array elements and string members select fields in the referenced ObjectRecord; each destination must exist in that snapshot. C pointers to `a[1]`, a nested row, or `point.y` link to that destination. Object identities include the observed type to distinguish a matrix, its first row, and scalar storage sharing an address. A C local whose declaration has not executed is `uninitialized`; this does not claim general initialization analysis after declaration.
